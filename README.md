# CQA · Conversation Quality Analytics

Прототип для Freedom Broker / Data Challenge: оценка работы оператора по настраиваемому чек-листу, доказательства по репликам и апелляции.

**Team Kiker** 

**Статус:** расчёты, хранение, импорт и интерфейс реализованы. Рабочий профиль — Ollama с Qwen3:30B на сервере NVIDIA/Brev; локальный интерфейс подключается к нему через SSH port-forward. Оценки не подменяются демонстрационными результатами. Точность относительно Ground Truth ещё не измерена.

## Запуск за минуту

Нужен Python **3.10+**. Внешние Python/JS-зависимости и сборка фронтенда не требуются.

```sh
cp .env.example .env
python3 server.py
```

Откройте <http://127.0.0.1:8765>. Сервер слушает только localhost. Для другого порта задайте `PORT` в `.env`. Для остановки нажмите Ctrl+C.

Локальная версия, подготовленная в ходе разработки, уже содержит `.env` со ссылкой организаторов и 65 DEV-диалогов в `data/dev.json`. После клонирования из GitHub этих приватных файлов нет: их нужно настроить/загрузить самостоятельно.

В `.env` укажите **полный подписанный URL GET для DEV** из кнопки на странице 3 руководства:

```dotenv
DATASET_API_URL=полная-ссылка-организаторов
```

Затем загрузите данные через интерфейс «Загрузить диалоги → Получить из API» или из терминала:

```sh
python3 manage.py fetch --group DEV
```

Контрольный набор загружается той же командой с новым `--group` или через поле группы в интерфейсе. Подпись URL не изменяется, меняется только параметр `group_id`. Если подписанная ссылка истекла, замените её в `.env`.

## Подключение AI

Поддержаны три HTTP-адаптера. Основной профиль проекта — Ollama/Qwen3:30B на NVIDIA/Brev. Перед запуском заполните `.env`, настройте SSH port-forward и **перезапустите сервер**. Наличие настроек не гарантирует доступность провайдера: это проверяется первым запросом.

Рабочий профиль:

```dotenv
AI_PROVIDER=ollama
AI_BASE_URL=http://127.0.0.1:11434
AI_MODEL=qwen3:30b
AI_API_KEY=
AI_REVIEW=true
AI_MAX_OUTPUT_TOKENS=8192
AI_TIMEOUT_SECONDS=300
AI_CONTEXT_WINDOW=32768
AI_THINK=false
```

На удалённом NVIDIA/Brev-сервере Ollama слушает loopback-порт 11434. Подключите его к локальному порту через SSH port-forward; публично открывать порт модели не требуется. Для Ollama ключ API не нужен.

Первый запуск — один диалог: `python3 manage.py evaluate --id p1-ru-001`. Затем откройте его в интерфейсе: будут доступны итог, критерии, цитаты и апелляции. Для следующих диалогов используйте «Запустить оценку» или выбор нескольких записей.

Для альтернативных HTTP-провайдеров адаптеры `openai` и `openai_compatible` остаются в коде, но не входят в рабочий NVIDIA/Qwen-профиль:

```dotenv
AI_PROVIDER=openai_compatible
AI_BASE_URL=https://адрес-провайдера/v1
AI_MODEL=модель-провайдера
AI_API_KEY=секретный-ключ
AI_REVIEW=true
```

Для совместимого API нужны `/chat/completions` и поддержка `response_format.type=json_schema`. Если провайдер поддерживает только свободный текст/JSON mode, потребуется другой адаптер; приложение явно сообщит об ошибке и не сохранит недостоверный ответ.

Qwen3:30B должна поддерживать structured output и достаточно уверенно работать с RU, KZ и EN. Перед массовым запуском проверьте 1–3 диалога. Секреты Brev/SSH вводятся только локально и не выдаются браузеру.

Для расчёта примерной цены задайте `AI_INPUT_PRICE` и `AI_OUTPUT_PRICE` — стоимость миллиона входных/выходных токенов в USD по тарифу вашего провайдера. Иначе стоимость показывается как неизвестная. Расчёт включает все полученные ответы, включая повторную проверку и исправление формата; провайдер может тарифицировать и неуспешные вызовы, поэтому это не замена его биллингу.

## Как устроена оценка

1. Сервер фиксирует снимок диалога и выбранную версию чек-листа; идентификатор диалога не передаётся модели как подсказка.
2. Модель получает весь транскрипт, роли, исходные временные метки, точные правила и разрешённые ответы. Бот и системные сообщения служат контекстом, оценивается оператор.
3. Ответ ограничен JSON Schema. Сервер проверяет комплектность критериев, ступени шкал, допустимость N/A, диапазон уверенности, ID реплик, проверенные участки и точное вхождение цитат в оригинал. При ошибке выполняется один запрос исправления; повторно некорректный результат отклоняется.
4. При `AI_REVIEW=true` модель ещё раз проверяет критерии, применимость и доказательства. Сохраняются первоначальный и проверенный ответы, расхождения и расход токенов. Это гипотеза повышения качества, а не доказательство большей точности; её нужно сравнить с одним проходом на отложенной разметке.
5. Итог вычисляется кодом: `100 × сумма(вес × доля выполнения) / сумма применимых весов`. Для шкал берутся только заданные ступени. N/A исключается из знаменателя. Округление — до двух знаков, HALF_UP. При отсутствии применимых весов результат `null`. Грубые ошибки — отдельные флаги, итог не обнуляется.

Фактическое наличие цитаты не доказывает верность интерпретации. Особенно важны ручная проверка неоднозначных N/A, полноты консультации и фактов, для которых не выдан внутренний регламент. Уверенность AI — самооценка, не измеренная точность. Дикция и интонация по транскрипту не оцениваются, записи звонков доступны по ссылкам.

Документация контракта OpenAI: [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses).

## Интерфейс и процесс проверки

- Диалоги: поиск, фильтры языка/статуса, групповой запуск, история результатов, экспорт полного JSON.
- Карточка: транскрипт, объяснения, кликабельные цитаты, проверенный участок, итог и секции, флаги, версия правил и SHA-256 источника.
- Чек-листы: добавление/удаление критериев, изменение формулировок, весов, шкал и N/A. Сохранение создаёт новую неизменяемую версию. Новые правила применяются при новом запуске, старые результаты не переписываются.
- Апелляции: комментарий по критерию → просмотр доказательств → подтверждение исходного ответа или новый допустимый ответ с обязательной причиной → автоматический пересчёт. Исходный AI-результат сохраняется.
- Импорт с прежним ID обновляет исходный диалог. Предыдущие оценки сохраняют старый снимок и отмечаются как устаревшие относительно транскрипта.

Без обязательного входа, как предусмотрено заданием. Роли подачи и проверки представлены отдельными действиями; это не разграничение прав пользователей. Сервер предназначен для локальной демонстрации, не для публичного доступа без дополнительной аутентификации.

## Импорт своих диалогов

Поддерживается ответ API с `data.records`, объект `{"records": [...]}`, массив или один объект:

```json
{
  "conversation_id": "new-001",
  "channel": "agent chat",
  "language": "RU",
  "transcript": [
    {"timestamp": "00:00", "speaker": "client", "text": "Где посмотреть тариф?"},
    {"timestamp": "00:05", "speaker": "operator", "text": "Здравствуйте! Я Анна. Откройте раздел «Кабинет»."}
  ],
  "audio_url": null
}
```

Роли: `operator`, `client`, `bot`, `system`. Каналы: `agent chat`, `voice call`. Языки: `RU`, `KZ`, `EN`. Исходные временные метки не преобразуются; звонки могут использовать ISO 8601. Присвоенные сервером `m0001` и далее позволяют ссылаться на реплики без неоднозначности. Максимальный импорт — 20 МБ / 1000 диалогов.

```sh
python3 manage.py import путь-к-файлу.json
python3 manage.py evaluate --id p1-ru-001
python3 manage.py evaluate --limit 3
python3 manage.py evaluate --all --output data/predictions.json
```

Обычный CLI-запуск обрабатывает один диалог, `--all` — весь набор. Вызовы API могут быть платными. Пакет сохраняет прогресс после каждой записи; ошибки отдельных диалогов указаны явно. UI-задача обрабатывает диалоги последовательно. При перезапуске сервера незавершённая задача отмечается прерванной; её оставшиеся записи можно повторить из интерфейса. Уже сохранённые результаты остаются в SQLite и не запускаются заново.

## Измерение точности

Ground Truth в выданных материалах не найден. Не используйте результаты самой модели как эталон. Для калибровки нужна независимая разметка и отдельная отложенная выборка с RU/KZ/EN, N/A и грубыми ошибками. Проводите сравнение одного и двух проходов на одинаковой выборке; не настраивайте промпт по контрольным десяти диалогам.

Эталонный JSON (значения ниже иллюстрируют формат, это **не разметка DEV**):

```json
[
  {
    "conversation_id": "new-001",
    "language": "RU",
    "criteria": {"contact": "yes", "needs": "na", "identity": "na", "consultation": "20", "empathy": "yes", "management": "10", "closing": "no", "gross_error": "no"},
    "total": 92.31
  }
]
```

```sh
python3 manage.py benchmark data/predictions.json путь-к-ground-truth.json
```

Отчёт: MAE итогового балла, точное совпадение по критериям, совпадение применимости, разрезы по языкам и критериям, пропуски и покрытие. Отсутствующие предсказания считаются ошибками при сравнении критериев. MAE считает только доступные численные пары, поэтому его нужно читать вместе с `total_pairs` и `missing_records`. Организаторы не раскрыли точную формулу ранжирования; эти метрики служат диагностикой.

## Проверки

```sh
python3 -m unittest discover -s tests -v
```

Проверяются арифметика, N/A, флаги, точность цитат, динамические критерии, неизменность истории, импорт, HTTP-процесс оценки и апелляции, отсутствие поддельных оценок без провайдера и сравнение с эталоном. HTTP-тесты используют тестовую модель-заглушку только во временной БД. Они подтверждают работу программы, не качество AI.

## Доработка после аудита: надёжность, интерфейс и измерение

Задачи оценки теперь сохраняются в SQLite. После обновления страницы прогресс восстанавливается; после остановки сервера незавершённая задача помечается прерванной. «Повторить оставшиеся» создаёт новый запуск только для неуспешных/незавершённых записей с исходными снимками диалогов и правил. Уже успешно сохранённые результаты не повторяются. Провайдер при повторе берётся из текущей конфигурации. Кнопка «Остановить» действует между запросами AI: текущий сетевой вызов может завершиться до остановки.

В карточке есть выбор одного прохода и повторной проверки. По умолчанию применяется `AI_REVIEW`. Быстрый режим не имеет доказанного преимущества по точности; сравнивайте режимы на независимой разметке. Неудачные ответы и неверные цитаты не сохраняются как оценки.

Дополнительные серверные настройки:

```dotenv
AI_MAX_OUTPUT_TOKENS=8192
AI_TIMEOUT_SECONDS=180
```

Ограничение ответа не заменяет дневной бюджет API. Для 429 учитывается Retry-After: задержка до 30 секунд ожидается автоматически, более длинное ожидание сообщается пользователю. 401/403, 404, timeout и обрезанный ответ различаются. Секретные тела ошибок провайдера не возвращаются клиенту.

Чек-листы проверяются по типам и границам до записи. Черновик редактора сохраняется в sessionStorage текущей вкладки и переживает F5; статус хранения показан рядом с редактором. Закрытие вкладки может удалить черновик — для постоянного хранения сохраните версию. Транскрипты в sessionStorage не записываются.

На рабочем экране увеличен текст, добавлены подписи навигации и переключатель «Диалог / Оценка» для узких экранов. Нулевые и частичные ступени отмечаются корректно. Средний балл считается по последним результатам текущей версии чек-листа. Очередь ручной проверки выделяет флаги, неопределённости, расхождения повторной проверки и открытые апелляции; это приоритизация, не доказательство ошибки AI.

### Независимая разметка и воспроизводимый эксперимент

```sh
python3 manage.py label-template --limit 18 --output data/human_review.json
python3 manage.py evaluate --limit 3 --resume --output data/predictions.json
python3 manage.py benchmark data/predictions.json data/human_review.json
```

Первая команда не вызывает AI: она создаёт приватный пакет с исходными диалогами, правилами и пустыми ответами. Эксперт независимо заполняет `criteria`, `total`, имя и заметки. Пустой шаблон нельзя считать Ground Truth. Языки выбираются по очереди; это исходный рабочий набор, не статистически репрезентативная выборка. Для конкретных диалогов используйте повторяющийся `--id`. Реальные звонки включайте только после проверки разрешённой обработки данных.

`--resume` пропускает только успешные результаты с совпадающими хешами транскрипта, чек-листа и эксперимента. Ищет их в output и истории SQLite. Сохраняет другие ID в файле; чекпойнт записывается атомарно с правами 600. Предыдущий успешный результат остаётся в истории, даже если новая попытка завершилась ошибкой.

Результаты содержат хеш промпта, конфигурацию генерации без ключа/URL, тип проверки и расходы каждого успешного вызова. Benchmark отдельно перечисляет отсутствующие, неуспешные и неполные результаты, покрытие итогов, матрицы ошибок и precision/recall грубых ошибок. Время p50/p95 относится к успешным результатам и не включает полностью неуспешные вызовы.

### Оценщик cqa-1.2-proof-review

Новые оценки включают отдельные факты `checks` для исходных правил контакта,
выявления потребности, завершения и грубых ошибок. Сервер проверяет точность цитат,
роль автора, первый ответ оператора, полноту проверенного участка и согласованность
ответа с фактами. Это не доказательство правильного понимания текста моделью.

Контракты хранятся в `cqa/proof_contracts.json` и применяются только при точном совпадении
смысла правила в его зафиксированном текстовом представлении: `rule`, `na_rule`, тип,
применимость N/A и шкала. ID, название и вес могут изменяться. При изменении текста
правила применяется обычная оценка по новой инструкции без старого специального контракта.
Даже изменение пунктуации отключает такой контракт: это намеренно консервативное поведение.

При включённой повторной проверке второй проход получает исходный диалог и правила,
но не первый ответ. Это та же модель, а не независимый эксперт; ошибки могут повторяться.
Расхождения ответов отправляют результат на ручную проверку. Обычно выполняются два
вызова, максимум четыре при исправлении недопустимых ответов; checks увеличивают объём
вывода и могут повысить расход токенов. Старые оценки сохраняются без пересчёта.

Проверки без сетевых обращений: `python3 -m unittest discover -s tests`.
Тесты проверяют протокол, а не точность LLM. Новый реальный прогон и сравнение с независимой

## Быстрая оценка и исправления 8 ноября

В карточке по умолчанию выбран режим «Быстро · выборочная проверка»: один проход для простых случаев, повторная проверка для звонков, сомнений, защищённых действий, нарушений, переспросов, изменённых критериев и ошибок доказательств. Режим не гарантирует обнаружение всех ошибок первой оценки; два прохода всегда и один проход остаются доступны.

CLI: `python3 manage.py evaluate --limit 3 --review-mode auto`. Полный режим: `--review-mode full`, один проход: `--review-mode single`. Новые режимы имеют отдельные хеши эксперимента; старые результаты не подменяются.

Ollama теперь получает явные `think=false` и `num_ctx=32768`; параметры можно менять через `AI_THINK` и `AI_CONTEXT_WINDOW`. Большее окно требует памяти. Добавлен контроль фактов идентификации и порядка проверки до защищённого действия, уточнены представление и завершение. Подробности и ограничения — [отчёт об оптимизации](docs/reports/2026-11-08/SPEED_QUALITY_UPDATE_RU.md).
