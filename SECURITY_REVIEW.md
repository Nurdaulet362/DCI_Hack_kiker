# Проверка безопасности CQA — 7 ноября 2026

Проверены исходники и локальное приложение с помощью ECC Security Review и ECC Chrome DevTools. Изменения проверены автоматическими HTTP-тестами и в браузере. Это ограниченная проверка прототипа, не сертификация и не гарантия отсутствия уязвимостей.

## Найдено и исправлено

### Перенаправление могло передать Authorization другому адресу

До исправления стандартный urllib-клиент при ответе 302 отправлял заголовок Authorization адресу из Location. Это воспроизведено на двух локальных серверах с фиктивным ключом. Реальные ключи для теста не использовались. Риск возникал бы при перенаправлении настроенного AI-провайдера на посторонний адрес; AI ещё не подключён, утечка реального ключа не установлена.

Добавлен общий клиент `cqa/network.py`, запрещающий перенаправления запросов AI и API организаторов. Регрессионный тест подтверждает, что второй сервер вообще не получает запрос. Если провайдер требует редирект, необходимо указать конечный проверенный адрес в конфигурации.

### Удалённый API мог быть настроен по незашифрованному HTTP

Теперь удалённым API разрешён только HTTPS. HTTP разрешён для localhost и буквальных loopback IP, чтобы сохранить поддержку Ollama. URL с логином/паролем и другие схемы отклоняются. Домен, похожий на localhost, не считается локальным.

### Права локальных файлов — дополнительная защита

Ранее `data/` имел режим 0755, DEV и SQLite — 0644. На проверенном Mac родительский Desktop уже имел режим 0700; доступ другого системного пользователя к данным не был доказан. Для независимости от расположения проекта теперь устанавливаются 0700 на каталог данных и 0600 на `.env`, базу и существующие основные файлы данных. Новая SQLite создаётся сразу с 0600. POSIX-права не заменяют ACL при развёртывании на Windows.

### Дополнительное усиление HTTP

- Ограничение чтения ответа AI до 4 МБ.
- Таймаут чтения входящих соединений 15 секунд.
- Отклонение cross-site Fetch Metadata и неоднозначных Content-Length/Transfer-Encoding.
- Заголовки Referrer-Policy: no-referrer, X-Frame-Options: DENY; CSP дополнена object-src 'none' и form-action 'self'.

## Что проверено

- XSS: вредоносные HTML-строки в ID, времени и тексте диалога не создают img/svg-элементы; обработчики не выполняются. Браузерная проверка затрагивала только временное состояние страницы и не сохраняла вредоносные записи в рабочую БД.
- `javascript:` в ссылке аудио не попадает в DOM как активная ссылка.
- Запросы к `.env`, SQLite, DEV JSON и попытки обхода пути получают 404.
- Чужой Host получает 403; чужой Origin и cross-site Fetch Metadata блокируют запись.
- SQL-подобный ID сохраняется как строка; таблицы остаются целыми. В коде используются параметризованные запросы.
- Проверены отсутствие ключей и подписанного URL в отправляемых исходниках, исключение приватных файлов из Git и отсутствие ключа в публичной конфигурации AI.
- Новые тесты проверяют запрет пересылки Authorization, допустимые URL и права файлов. Общая проверка: `python3 -m unittest discover -s tests -v` — 22 теста.

## Границы и оставшиеся риски

Приложение слушает только 127.0.0.1 и рассчитано на доверенного пользователя компьютера. Обязательной авторизации и разграничения ролей нет по условиям демонстрации: локальный процесс с доступом к порту может читать данные и менять решения. Для публикации в интернет нужны аутентификация, серверные роли проверяющего, TLS на входе, ограничения запросов и контроль затрат. Текущую конфигурацию нельзя считать готовой к публичному размещению.

Защита от prompt injection сформулирована в системном промпте, доказательства проверяются кодом. Это не доказывает устойчивость самой модели: провайдер ещё не подключён, реальные атаки на LLM не проверялись. Модель не имеет инструментов, доступа к ключам или функций выполнения команд. Качество и устойчивость её решений требуют отдельной проверки после подключения.

Полномасштабное нагрузочное тестирование, анализ ОС, проверка реального AI-провайдера, полного GitHub-аккаунта и всех исторических веток в область этой проверки не входили. Сторонних runtime-пакетов Python/JS у приложения нет; безопасность стандартной библиотеки зависит от обновлений установленного Python.
