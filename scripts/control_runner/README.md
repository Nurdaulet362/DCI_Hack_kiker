# Воспроизведение контрольного прогона FBroker

Это код самостоятельного inference через Ollama, использованный для обработки контрольных FBroker-чатов. Он вызывает основной оценщик из `cqa/`, проверяет доказательства и сохраняет реальные ответы. Исходные диалоги, predictions, trace и credentials в эту публичную папку не входят.

Четыре файла `run.py`, `retry_errors.py`, `retry_consistency.py`, `run_control.py` скопированы побайтово из замороженного контрольного запуска. Их SHA-256, а также хеши использованного ядра и стандартного чек-листа перечислены в `frozen_code_sha256.json`. Для контрольного прогона используется только точка входа `run_control.py`; остальные три файла предоставляют базовый, ролевой и согласованный decoder adapter.

## Подготовка без модели и сети

Фактический контрольный прогон использует ядро из commit `86e586c6754c10dcedf37521a5c80d093a73f665`. Более поздние изменения `main` сохраняются; для повторения извлеките старое ядро в отдельный приватный каталог. Из корня репозитория, с разрешённым исходным ответом API FBroker и точным снимком чек-листа:

```sh
umask 077
mkdir -p data/control
mkdir data/control/core
git archive 86e586c6754c10dcedf37521a5c80d093a73f665 cqa config | tar -x -C data/control/core

python3 scripts/control_runner/prepare_control.py \
  --project data/control/core \
  --source data/control/FBroker-source.json \
  --checklist data/control/checklist.json \
  --validate-only

python3 scripts/control_runner/prepare_control.py \
  --project data/control/core \
  --source data/control/FBroker-source.json \
  --checklist data/control/checklist.json \
  --output data/control/frozen-run

python3 data/control/frozen-run/run_control.py --validate-only
```

Примеры путей следует заменить на фактические приватные файлы. Подготовка принимает только успешный API-объект группы `FBroker` с ровно 10 уникальными чатами, нормализует реплики основным кодом проекта и копирует точные байты чек-листа. SWAP отвергается. Код ядра и адаптеры должны совпасть с зафиксированными хешами. При отличии используйте выделенную копию ядра из указанного commit; не обновляйте хеши для выдачи изменённого процесса за прежний.

В закрытый каталог копируются четыре адаптера, `cqa/`, `config/`, `conversations.json`, `checklist.json` и `manifest.json`. Каталог имеет права 0700, файлы — 0600. Непустой выходной каталог не перезаписывается. Подготовка и оба режима `--validate-only` не вызывают модель, не обращаются к сети и не арендуют GPU.

## Фактическая модель и запуск

Использована **Qwen3:30b Q4_K_M**, Ollama **0.40.15**. Полный digest:

```text
ad815644918f0eaab341c12b67837cc6dd4562342cdaf118f83d5d554cb37226
```

Контрольный runner проверяет digest через `/api/tags` перед обработкой. Изменяемого имени `qwen3:30b` для воспроизведения недостаточно: скачанный файл должен соответствовать полному digest. Параметры адаптера фиксированы: `temperature=0`, `think=false`, `num_ctx=32768`, `num_predict=8192`; основной оценщик использует выборочную повторную проверку `auto`. Фактические запросы сохраняются в журнале.

На машине должен быть установлен Ollama с этой моделью, доступный только через `http://127.0.0.1:11434`. Можно запускать runner на GPU-машине либо использовать защищённый SSH port-forward. Проверяйте память, доступность модели, оставшийся денежный лимит и отдельный срок удаления облачной машины до начала inference.

Пример запуска с пределом 30 минут из подготовленного каталога. Выбирайте срок по оставшемуся денежному лимиту: он не гарантирует завершение всех 10 чатов, а повторные проверки могут увеличить время:

```sh
cd data/control/frozen-run
RUN_DEADLINE_UNIX="$(python3 -c 'import time; print(int(time.time()) + 1800)')" \
  python3 run_control.py
```

`RUN_DEADLINE_UNIX` — абсолютная Unix-метка времени. Она ограничивает запросы runner, **но не удаляет GPU** и не останавливает инфраструктурный биллинг. Автоматическое удаление машины и проверка удаления организуются отдельно. Нельзя рассчитывать на закрытие SSH или сон ноутбука как на остановку расходов.

При наличии `predictions.json` нужен `--resume` и новый допустимый deadline. Возобновление повторно использует только валидные записи с совпавшими входами, чек-листом и экспериментом. Версию модели, правила и файлы во время контрольного запуска менять нельзя. Все 10 ID изначально имеют явную запись ошибки до попытки; после каждой попытки checkpoint записывается атомарно. Ошибки сохраняются, а не заменяются нулевыми оценками.

## Выгрузка

Приватный `predictions.json` преобразуется в официальный формат скриптом `scripts/export_submission.py` с `--project data/control/core`, как описано в `results/README.md`. Для точного PROD-экспорта используется ядро того же commit `86e586c6754c10dcedf37521a5c80d093a73f665`, а также исходные диалоги и чек-лист фактического запуска. В Git отправляются `results/dev/results.json` и `results/prod/results.json`, без полных исходных транскриптов и логов. Храните приватный manifest и результаты для сопоставления хешей.

Проверка формата, схемы и воспроизводимости не измеряет точность AI. Ground Truth не передаётся модели; сопоставление с независимым эталоном выполняется отдельно.
